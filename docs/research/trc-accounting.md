# TRC wire accounting for exact sessions

PollicinoNet uses **Transmission Reconstruction Cost (TRC)** to reason about the bits required to obtain verified information, not just the nominal application payload.

This module currently covers the exact-session wire segment. Discovery, rendezvous and future FEC components remain separate additions to the full end-to-end TRC.

## Non-overlapping accounting

For one successful PNF1 exact transfer, wire bytes are split into four non-overlapping classes:

```text
primary data
+ primary ACK
+ retransmission data
+ retransmission ACK
= accounted wire bytes
```

`primary data` means exactly one encoded PNF1 transmission per frame. `primary ACK` means one successful ACK per frame. Any additional transmissions are charged only to the retransmission classes.

This prevents a common accounting error where total data bytes already include retries and the retry bytes are then added a second time.

## Logical session classes

A resumable exact-session step separately records total accounted bytes for:

- manifest transfer;
- receiver availability summary;
- missing chunk transfer.

The same step also exposes the orthogonal primary/retransmission breakdown above.

Therefore both equalities are enforced:

```text
manifest + availability + chunks
=
primary data + primary ACK + retry data + retry ACK
=
step wire bytes
```

The session state enforces the same equality cumulatively across resumed steps.

## Deterministic simulator semantics

`ScarceLinkProfile` knows whether each modeled data frame and ACK was transmitted. Its wire accounting is therefore exact **inside the deterministic model**:

```text
wire_accounting = deterministic_model_exact
```

This is not a claim that the simulator is an exact model of a physical deployment. It means only that the bytes generated by that simulation are completely known.

## Physical RF replay semantics

An HW-006 untethered timeout has an observability gap. The local transmitter definitely emitted the outward frame, but the trace cannot tell whether the remote node emitted a response that was subsequently lost.

For physical replay:

```text
local TX data bytes       = exact
confirmed returned ACKs   = lower bound
unobserved remote replies = unknown
```

The accounting label is therefore:

```text
wire_accounting = local_data_exact_remote_ack_lower_bound
```

`unknown_remote_failure_count` counts failed replay attempts for which remote response traffic cannot be resolved. Those unknown bytes are **not assigned a fabricated numeric value**.

## Resumed-session invariant

A resumed session cannot silently switch from deterministic exact accounting to physical-replay lower-bound accounting, or vice versa. Mixing those semantics would create a cumulative TRC number with no coherent interpretation.

If a different evidence source or accounting mode is required, start a separate measurement/session series and compare them explicitly.

## Current boundary

The implemented breakdown is the exact-delivery wire slice:

```text
manifest / availability / chunks / ACKs / retries
```

Full PollicinoNet TRC will later add non-overlapping components for:

```text
discovery
+ rendezvous
+ resolved manifest/control
+ exact payload/reference/residual
+ FEC where used
+ ACK/retry traffic
```

No component should be counted twice simply because it belongs to both a logical protocol phase and a physical transmission category.
