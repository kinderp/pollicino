## Priority for the Messina-province teaching network
1. **UC-221:** demonstrate at once that object delivery, application validation and committed use are different events; supports DNA/DNATrace, Raiatea and sensor applications.
2. **UC-224:** once UC-008/178/196 collect credible contact evidence, measure how well probabilistic contact forecasts match held-out experience; prevents overconfident routing choices.
3. **UC-223:** create an accessible school-based physical experiment integrating LoRa relay handoff, instrumentation, measurement uncertainty and provenance.

UC-222 is a safe *fictional emergency drill* only. UC-225 is an AI supply-chain/edge-AI security laboratory with **synthetic data only**, not a real malware experiment.

## Cross-case novelty boundaries
- UC-221 differs from UC-098 forwarding receipts, UC-168 custody and UC-215 robot handoff by requiring a separate **authorized application acceptance** event.
- UC-222 differs from UC-107 cache freshness and UC-132 update/cancel lifecycle by deciding **what an offline human-visible screen must show** under uncertainty.
- UC-223 differs from UC-037 mobile transects, UC-166 sensor calibration, UC-187 generic science rounds and UC-197 weather ferry through **paired fixed-site comparison with crossover and missingness controls**.
- UC-224 differs from UC-169 probability-based routing and UC-183 routing comparison: it **scores probabilistic contact forecasts themselves** on held-out observed windows, considering missing logs (UC-178).
- UC-225 differs from UC-114 train/test overlap, UC-205 dataset permissions and UC-209 label disputes: it gates **synthetic data poisoning/admission risk**, with explicit quarantine.

## Software tests possible immediately
All tests are specified, none executed in this documentation-only update. Start with independent two-process simulated application receipts (UC-221), then an emulated kiosk with delayed cancellation and RTC loss (UC-222). The sensor comparison script (UC-223) can use seeded synthetic data. Contact forecast Brier/reliability scoring (UC-224) can use generated truth. Toy poisoning classifiers and canary gates (UC-225) need no radios.

## Physical test prerequisites and truth boundaries
Use institutional approvals and voluntary participation (UC-217); begin at fixed supervised school checkpoints, not private residences or individual commute paths. Verify radio configurations and applicable regional spectrum rules; frozen PHY/MAC stays untouched. Measure actual TX/RX events, contact windows and byte verification (UC-221/224), real temperature/humidity sensor siting and calibration (UC-223), actual kiosk state under delayed connectivity (UC-222) and exact artifact transfers (UC-225). Never label simulations as RF performance; no certified public alert, heat-health or AI-security guarantees.
