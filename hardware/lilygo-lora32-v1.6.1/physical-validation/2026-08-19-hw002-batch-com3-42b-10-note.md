# HW-002 first paced bench batch — COM3 initiator

Observed on 2026-08-19 with the frozen HW-002 profile (`868.100 MHz`, `BW125`, `SF7`, `CR4/5`, `10 dBm`) and `42`-byte H2 PING/PONG frames.

- 10 attempts, 10 successes, 0 observed failures.
- RTT mean: `181.5627 ms`; min `181.077 ms`; max `182.037 ms`.
- Nominal two-frame RadioLib time-on-air: `176 ms`; about `96.94%` of mean RTT.
- Initiator TX blocking mean: `89.7141 ms` vs nominal single-frame ToA `88 ms`.
- Mean responder-observed PING RSSI/SNR: `-38.1 dBm / 9.625 dB`.
- Mean initiator-observed PONG RSSI/SNR: `-39.7 dBm / 9.95 dB`.
- Pacing: `1%` experimental TX-occupancy input, `8.8 s` minimum start interval.
- Total observed elapsed time: `79.375 s`.

## Planner estimate discrepancy

The planner reported about `88 s`, while the executor completed in `79.375 s`. The executor pacing is correct: ten transaction starts contain only nine inter-start waits. The displayed wall-time estimate includes an unnecessary post-final interval. For an all-successful 42-byte batch, `9 × 8.8 s + 0.176 s ≈ 79.376 s`, matching observation.

The planner code is intentionally left unchanged until the mirrored COM4-initiator run is completed, so both directions use the exact same runner. This is a display/estimate issue, not an RF pacing failure.

## Scientific boundary

`0/10` observed failures does not establish a true zero packet-loss probability. This is a same-bench repeatability checkpoint only. Larger sample counts and controlled distance/environment sweeps are required for loss-rate and range claims.
