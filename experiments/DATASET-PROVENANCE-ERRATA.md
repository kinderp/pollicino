# Dataset provenance errata — PILOT-001 / PILOT-002

## Summary

During PILOT-003, a clean GitHub Actions checkout attempted to reconstruct the `pollicino-self-v1` splits using the committed `experiments/pilot-001/prepare_data.py` recipe. The generated bytes did **not** match the split sizes and SHA-256 values recorded by PILOT-001 and reused by PILOT-002.

| test | 12711 | `3ac9c682bacb359197c5070388509281ac49e775723805304dba341338b88a33` |

## Consequence

The numerical results in PILOT-001 and PILOT-002 remain records of the runs that were executed, but their original dataset bytes cannot be reconstructed from the committed Git tree alone. The most likely explanation is that the original local workspace contained additional or different files that matched the selection recipe but were not committed in the referenced tree.

Therefore:

- do **not** treat PILOT-001/002 absolute bpb values as reproducible from Git alone;
- do **not** compare PILOT-003 absolute bpb values directly against PILOT-001/002 as if only the architecture changed;
- PILOT-003 includes the PILOT-002 winner architecture (`d_model=48`, 2 layers, context 32) as an internal control on the new clean dataset;
- `pollicino-self-v2-clean-git` is the first self-corpus baseline explicitly verified from a clean checkout.

## Policy going forward

A POLLICINO dataset is considered reproducible only when a clean checkout regenerates the declared split sizes and SHA-256 values. Future pilots must record the clean checkout commit, selection recipe, split hashes and any externally materialized corpus version.
